# 개요

## 문제

프로젝트 수가 늘어나면서, 사람이 손으로 각 프로젝트의 품질(QC/QA)을 반복 점검하는 방식은 확장성에 한계가 있다. 기존 정적 분석 도구와 CI/CD 파이프라인은 코드 레벨의 문제는 잡아내지만, 실제로 실행해봐야 드러나는 문제(실행 중 발견되는 버그, UX 흐름의 부적절함)는 다루지 못한다.

이 문제는 능력에 따라 성격이 다르다: 실행 중 상호작용을 통한 발견은 사람에게 시간을 아무리 줘도 구조적으로 하기 어려운 영역이고, 반복적인 점검은 인력을 늘리면 원리적으로 해결되는 영역이다.

## 대상 사용자

개별 프로젝트를 만드는 개발자 본인. 릴리스 전 셀프 QC로 사용하며, 조직 전체를 조망하는 대시보드는 이 프로젝트의 1차 목표가 아니다.

## 이 프로젝트의 역할

Momos는 검사기관처럼 동작한다 — 대상 프로젝트에 아무것도 설치하지 않고, 프로젝트가 선언한 목적·비전·범위를 이해한 뒤, 실제로 실행하며 근거 있는 지적을 담은 검사 결과서를 만든다. 개발 기간 내내 함께하는 지속적 동반자이지, 커밋을 막는 실시간 게이트가 아니다.
